# Work log: 2026-11-21

**Goal today:** get the data onto the Hub without downloading 342 GB, decide how to split it, and wrap the whole pipeline in one resumable script.

## Outcome in one line
`download_data.py` fetches only the 8,133 files the CSV needs (29.9 GB instead of ~342 GB), `create_splits.py` holds out 17 whole studies for validation, `upload_to_hub.py` pushes one shard per study named after its split, and `run_all.sh` runs everything with checks. **The upload is in progress**: at the last check 33 of 87 shards were in the repo (24 train, 9 validation), and the Hub already reports both splits.

## Timeline
1. **Leakage check (was my assumption, so tested it).** On the 8 on-disk studies, consecutive image ids are no more alike than random pairs from the same study (thumbnail correlation equal in every study). Images *within* a study are very alike though (correlation 0.97-0.997 in Studies 04 and 87). So no block-splitting by id; hold out whole studies. Weak test: small samples, and it cannot see shifted overlapping fields.
2. **How the data is shared.** One zip per study (`Study_01` ... `Study_87`, 342 GB total). Studies 26, 27, 74, 75 are split into parts (`.z01`, ...). Study 27 is 113 GB because it holds 17,626 files (~6.4 MB each); we need 591 of them. The server answers HTTP range requests.
3. **`download_data.py`.** Reads each zip's index with range requests, fetches only the wanted files, checks each against its CRC, writes `.part` then renames. Handles zip64 and split archives (own index parser, parts treated as one virtual file). Resumable (skips files already on disk). Checked: 252 of 252 files byte-identical to local copies (Studies 04, 24, 59); split Study 74 392 of 392 files, all CRC-checked and readable. Dry run over all 87 studies: **29.9 GB**, and **every CSV file exists in its zip (0 missing)**. Added `requests` to the project.
4. **Circular dependency, found by you.** On a clean machine `reconcile.py` needs Study 59's image files, `create_pairs.py` leaves those rows out until it has run, and the pair download only fetches what the CSV lists. My earlier dry run passed only because `computed_best_focus.csv` was already saved. Fix: `download_data.py --stacks` fetches the full stacks that still need a best z (Study 59 PC, 228 files, 1.5 GB) before reconcile, and `--prune-stacks` deletes the unneeded slices after. Verified from a clean state: reconcile recreated `computed_best_focus.csv` **byte-identical**.
5. **`run_all.sh`** (steps 0-7: preflight, validate, stacks, reconcile, pairs, download, splits, upload; flags `--dry-run`, `--delete`). Checks between steps (study count, 0 out-of-range best_z, nothing left to compute, no rows left out, download size vs free disk, all files present, splits sane, shards in the repo under the right split). Prints a banner, `check ok` lines and a timed `PASSED` per step. Tested: dry run, forced failures (wrong study count, not enough disk, broken split), clean-state run from deleted CSVs. Kept bash rather than a Makefile (state is the Hub and remote files, not local timestamps; make is not on Windows by default).
6. **Resume gap fixed.** With `--delete`, a re-run would have re-downloaded studies already uploaded. Step 5 now asks the Hub which studies are done and only fetches the rest.
7. **`upload_to_hub.py` rewritten for batches.** One parquet shard per study, several shards per commit (`--max-gb 3`, about 12 commits; first commit was 16 studies), `upload_folder` with retries on rate limits, skips studies already in the repo, `--delete` frees each batch's images. Shards are built in a temp folder on C: and removed after each commit. Measured on Study 04: shard = 0.99x the images, plus an equal-size temporary Arrow cache (deleted after each study).
8. **`create_splits.py`.** Study-level holdout found by a seeded random search (20,000 tries) so each organelle gets about 10% in validation, none above 15%, at least 3 held-out studies each. Result (seed 0): **17 studies, 263 of 2,743 images (9.6%)**: nucleus 10.0%, mitochondria 10.5%, tubulin 12.2% (4 studies), actin 12.1%. Giants (Studies 25, 26) stay in train. Checked: same seed gives an identical file, every pair row has a split, no study on both sides, all 204 two-input images stay together (Study 76 is the only held-out one).
9. **Splits wired into the upload.** Shards are named `train-Study_XX.parquet` / `validation-Study_XX.parquet`, so the Hub shows real `train` and `validation` splits (no dataset card needed). The upload refuses to proceed if a study is already in the repo under the other split. Verified against the real repo: `get_dataset_split_names` returns `['train', 'validation']`.

## Decisions
- Per-study folders kept (a flat folder would work, since filenames are unique across studies, but it buys nothing and loses per-study batching).
- Local full stacks for the 8 earlier studies deleted by you; only the CSV's files are kept from now on.
- Splits are by whole study. No within-study holdout (offered, not requested).
- **Not decided:** using neighbouring z slices as augmentation. Default is best-focus only. The keep-list holds only best-focus files, so neighbours would need to be fetched again.
